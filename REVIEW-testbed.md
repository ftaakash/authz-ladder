## Verdict

The isolation itself is real: the live `pilot08_dsp` network is `internal: true` and the container has no host port mappings, and every digest, `latest`-tag and LF check passes, with keys correctly gitignored. The testbed is not yet trustworthy as a basis for tests. The bring-up script cannot succeed against its own internal network (finding 1), compose still declares host port publishes that only a Docker quirk neutralises (2), and the isolation proof rests on dirty-tree, R1-only, unconditional-BLOCKED probes (9, 10). The written record has drifted behind decision D5: duplicate D5 rows, a stale D4 oracle rule, a report index that still says the choice is open, a "verified" `iam-mock` claim with no stored evidence, and several quoted outcomes (EGRESS_OK, fakebearer 401, 42 IATP classes) that exist nowhere in `env/` or `results/`. No scope violation (no third-party probing, no exploit output, no candidate findings in git) was found. Fix findings 1, 2, 4–7 and 12 before the vanilla-EDC SUT replaces this compose file, and re-run the isolation check on a clean commit against the new SUT.
