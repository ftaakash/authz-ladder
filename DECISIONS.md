**D11 amendment (2026-10-24) — identity bootstrap method (user: "bootstrap identities, stop before credentials").**
The IdentityHub BOM ships **no** first-participant/super-user bootstrap (verified in source and the built jar), so a `did:web` document only exists once a participant context + keypair are created — which the Identity API cannot do unauthenticated. Smallest documented route used: a tiny tracked seed `ServiceExtension` (`kc2/identity/src/.../Kc2SeedExtension.java`) that, in `start()` (after all `initialize()` so the `aes` encryptor is registered), calls EDC's **official** `IdentityHubParticipantContextService.createParticipantContext(manifest)` for one configured participant. This generates the Ed25519 keypair (private key held only in the ephemeral in-memory vault, never written to disk) and publishes the participant's `did:web` document via the local DID publisher. The extension holds **no secrets** (ids/DIDs/aliases via config only) and is tracked under D9. Two incidental additions, both tracked and secret-free: (a) the `aes-encryption` module is added to the identityhub launcher because the participant-config store encrypts with `aes` by default but the BOM ships no algorithm provider; the extension seeds a fresh random 256-bit AES key into the in-memory vault at `edc.encryption.aes.key.alias` at boot (ephemeral, never persisted). (b) Evidence: `kc2/env/identity-smoke.csv` (did:web cross-resolution 8/8). **Held back per the user:** MembershipCredential issuance/storage, BDRS-credential wiring, and the DCP handshake — none implemented. Private keys stay under gitignored `testbed/.secrets/kc2/`.
